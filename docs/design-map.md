# 线上 D&D 虚拟桌面设计决策地图

Labels: wayfinder:map
Status: resolved

## Destination

通过与用户逐轮对话，完成可供后续开发使用的产品与架构设计：明确首版范围、领域概念、权限、地图交互、角色卡、战斗与日志，以及模组模板和自动结算的扩展边界。本轮工作只做设计，不实现业务软件。

## Notes

- 使用 Wayfinder 及同插件内的 grilling、domain-modeling 工作流。对话中的用户选择是决策依据；未回答的建议不能当作已确认需求。
- 使用本地 Markdown tracker：本文件为地图，issues/ 下每个文件为一张子票。票的 Type、Status、Assignee 和 Blocked by 记录类型、领取和依赖；以编号顺序选取未解决、无阻塞且未领取的票。
- 用户已确认：服务于固定伙伴，电脑浏览器优先；手机首版支持角色卡、日志、资源维护与掷骰。
- 用户最新已确认：首版 DM 手动裁定；规则基线统一为 5R（2024 修订版）+ DM 选用的扩展，替代初始的 2014 基础混用新版内容方案。旧扩展逐项确认兼容性，不静默套用旧机制。
- 用户已确认：后续作者制作结构化模组包，由 DM 定制、导入和开团；文档识别转换留作更晚的辅助功能。
- 用户已确认：模组模板阶段可加入攻击自动结算；现阶段预留接口。战斗日志必须能点开查看结算依据。
- 用户已确认：暗骰只向 DM 开放；暗骰结果先交给 DM，由 DM 决定是否及何时应用或公开。
- 用户已确认 Java/Spring Boot + React/TypeScript + PixiJS；首版使用服务器，保存并支持未来迁移至 DM 本机。内网穿透和 P2P 只讨论可行性，后续再探索实现。具体版本基线与容量估算已经研究，尚未构建联调或压测。
- 用户比较 MySQL 后明确选择 PostgreSQL，云端与 DM 本机统一使用；初始版本基线沿用 18.6。素材单独保存在持久目录，首版不维护多种业务数据库引擎。
- 用户已同意阶段划分与每日自动备份（默认最近 7 份）。首版团内 RP 文字、图片、引用与机器人操作，所有 RP 历史长期保存；备份轮换不清理战役记录。QQ 对接和旧日志导入后置，首版自动投初始先攻。
- 整体设计资产见 [设计方案 v0.2](product-design.md)，作为设计基线；用户已在2026-10-18授权进入业务编码，实际联调结果在应用仓库验收记录维护。
- 词汇表见工作区根 CONTEXT.md。此工作区包含规则查询资料，不能将知识库正文当作产品内置内容；具体规则结论另行查证。

## Decisions so far

<!-- 新的设计决策只在对应子票保存完整答案；本节仅追加已解决子票的链接与一句摘要。上面的 Notes 是用户在建图前已明确的工作约束。 -->

- [确定混合规则与首版角色卡的支持边界](decisions/01-rules-and-character-boundary.md)：当前 5R 基线下的半自动角色卡、可切换内容准入、手动资源维护，资料库与自定义条目并行。
- [确定地图交互、棋子控制与信息可见性](decisions/02-map-control-and-visibility.md)：二维方格地图、按角色行动与共享授权、手动遮盖、一人多角；后续支持移动预算提示、自动视野和分队地图。
- [确定手动裁定、未来自动结算与日志详情的统一流程](decisions/03-combat-resolution-and-log.md)：引导攻击与角色级回合，结算依据留存并按权限展示，错误留痕更正；未来自动结算默认由 DM 确认。
- [确定模组模板的内容、定制、导入与版本生命周期](decisions/04-module-template-lifecycle.md)：完整冒险包、独立定制副本与战役进度、DM 可编辑触发操作；模板更新由 DM 选择应用，条件触发留待后续。
- [比较集中式服务、DM 本机托管与 P2P 联机](decisions/09-research-network-topology.md)：P2P 仍需信令与可能的中继；本机托管与穿透可行，带宽收益取决于具体数据分发方式。
- [核实技术栈版本与兼容基线](decisions/08-research-stack-versions.md)：已核实 Java 25、Boot 4.1.1、React 19.3.0、Vite 8.3.4 等正式发行基线与文档兼容条件，尚未实际构建联调。
- [确定访问方式、部署约束与技术架构](decisions/05-platform-and-architecture.md)：首版服务器、账号邀请与 PostgreSQL，支持持久化和迁移，技术版本与资源需求有研究基线；P2P 与穿透实现后置。
- [确定首版角色卡字段、计算清单与资料库收录范围](decisions/07-character-fields-and-content-catalog.md)：完整半自动角色卡与导入导出、状态到期提醒；首版规则检索与便捷填卡，未收录内容仍可手动维护。
- [确定 RP 文字频道、机器人操作与长期记录](decisions/11-rp-channel-and-bot-workflow.md)：软件内文字/图片/引用、常用投骰与角色操作、自动初始先攻，全部 RP 历史与附件长期留存；QQ 接入和旧日志导入后置。
- [核对 2014 自动先攻的规则边界](decisions/12-research-initiative-2014.md)：仅保留历史对照，当前先攻依据已切换到 5R 核验。
- [核对 5R 2024 自动先攻及规则版本边界](decisions/13-research-initiative-2024.md)：本地开放 SRD 5.2 核验了新版先攻、突袭、平手与角色卡类别，保留扩展边界。
- [将设计规则基线切换为 5R 2024 加扩展](decisions/14-switch-rules-baseline-to-5r.md)：按用户最新决定统一切换基线，角色卡、检索、先攻、模组、自动化和验收同步到 v0.2。

- [确定首版、模组与自动化阶段的交付边界和验收方式](decisions/06-release-boundaries-and-acceptance.md)：用户授权按框架、TDD、实现与验收分工开工，指定应用仓库及目录结构；执行状态另见实施路线。

- 首版 P2P、穿透工具集成和第二套联机实现；用户仅要求本轮讨论可行性，后续再探索对应版本。
