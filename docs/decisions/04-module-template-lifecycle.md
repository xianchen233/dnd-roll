# 确定模组模板的内容、定制、导入与版本生命周期

Parent: ../design-map.md

Type: grilling
Status: resolved
Assignee: Codex /root
Blocked by: 01, 02

## Question

结构化模组包包含哪些内容，作者如何制作，DM 在导入前后如何定制？模板、素材、规则依赖与战役进度如何隔离，如何处理重复导入、缺失依赖、更新与跨团复用？

## Comments

- 用户对完整冒险模组、可编辑副本、选择性更新和 DM 手动触发四个选择均回答 A，并强调 DM 必须能修改定制。

## Answer

1. 模组包支持章节、场景、地图、预摆单位、遭遇配置、DM 说明、可公开图片与文字资料、道具与奖励，以及引用的规则内容。各部分可留空，以便同一格式承载小场景与完整冒险。
2. 流程为导入模板库、创建可编辑副本、DM 定制、创建战役。保留模板原件；定制副本可另存模板并导出。由同一模板创建的不同战役分别保存单位状态、生命值、日志和剧情进度。
3. DM 可以修改地图、单位、剧情、规则选用、遭遇配置及一键触发的操作组合；不是只能填写作者预设的少量参数。后续增加条件触发时，也应允许 DM 修改条件、执行操作和确认方式。条件自动触发不是首个模组阶段的已承诺能力。
4. 作者发布新版时，现有副本和战役保持原版本。由 DM 选择是否更新及更新哪些内容，对冲突明确选择保留版本；不得直接覆盖本团进度。历史日志保留当时依据，不随模板更新重算。
5. 首个模组阶段由作者配置操作，由 DM 手动触发，例如揭露一组敌人、展示资料、启动遭遇。条件自动推动剧情留待后续，与攻击自动结算分别推进。
6. 导入、依赖检查、稳定内容身份、版本对比和导出是模组接口的设计工作。具体文件格式和缺失依赖处理属于待汇总的设计建议，不能把未讨论的自动修复或强制覆盖行为记作用户确认。
